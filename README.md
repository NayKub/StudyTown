# My Little Town (เมืองเล็กของฉัน)

A study timer that builds a town. Every minute you study adds to an isometric town
that starts as an empty plot and grows into a metropolis over about 80 hours.

One codebase, three targets: web, Android and iOS, using [Capacitor](https://capacitorjs.com).

## Features

- Study timer (15 / 25 / 45 / 60 minutes or a custom length), pause and early finish
- Town that grows and upgrades with total study time, with residents walking around
- Daily study log with 7 / 14 / 30 day charts and per-session times
- Thai and English (i18next), switchable in Settings
- Works fully as a guest, with all data stored on the device
- Optional account (Firebase): email sign-up and log-in, password reset, email verification,
  cloud backup of the town, and account deletion
- Friends: add by friend code or exact email, accept or decline requests, see each other's
  rank, minutes today and streak, and visit a friend's town
- Native extras: "time's up" notification when the app is in the background, haptics,
  optional keep-screen-on, and a running session survives the app being closed

### How the code is organised

- **Dependencies point one way:** `features` and `render` use `core`, `platform`, `i18n` and `ui`;
  `core` uses nothing. `main.js` is the only file that knows about every feature.
- **Pure logic lives in `core/`** and takes its inputs as arguments, so it can be tested without
  a browser. Anything that touches the DOM, the clock, storage or the network stays outside it.
- **One state object.** Features read and write `G` from `core/state.js`; only `main.js`
  replaces `G.state` wholesale (when a cloud backup is merged in).
- **The outside world is behind `platform/`.** Features never import Capacitor or Firebase
  directly, which is what lets `cloud-mock.js` stand in for the real backend.
- **Modules do nothing at import time.** Each feature exports an `init…()` that `main.js` calls.
- **No magic numbers:** durations, sizes and limits are named constants at the top of each file.
- **Every user-facing string goes through `t()`** and exists in both locale files.

## Requirements

- Node.js 22+
- Android: Android Studio Otter (2025.2.1) or newer
- iOS: a Mac with Xcode 26 or newer

## Firebase setup (for accounts and friends)

Without this the app runs in guest-only mode and hides the account features.

1. Go to [console.firebase.google.com](https://console.firebase.google.com), **Create a project**
   (Google Analytics can be off). The free Spark plan is enough.
2. **Build > Authentication > Get started > Sign-in method > Email/Password**: enable it (leave
   "Email link" off).
3. **Build > Firestore Database > Create database**: choose a location close to your users
   (for Thailand, `asia-southeast1` Singapore), start in **production mode**.
4. **Firestore > Rules**: replace everything with the contents of `firestore.rules`, then **Publish**.
5. **Project settings (gear) > General > Your apps > Web (`</>`)**: register an app (no hosting),
   then copy the `firebaseConfig` values into `src/firebase-config.js`.
6. Optional: **Authentication > Templates** to change the sender name and language of the
   verification and password-reset emails.

Do not add API key restrictions by HTTP referrer: the iOS app runs from `capacitor://localhost`.

Security rules are tested in CI against the Firestore emulator (`npm run test:rules`, needs Java 21).
To deploy rules from the command line instead of step 4: `npx firebase deploy --only firestore:rules`.

## Run it

```bash
npm install
npm run dev          # in the browser, http://localhost:5173
npm run dev:mock     # same, with a fake backend so you can try accounts and friends offline
                     # (demo users: mint@example.com / password, friend code MNT-234)
npm run android      # build, sync, open Android Studio, then press Run
npm run ios          # build, sync, open Xcode (Mac only), then press Run
```

After changing anything in `src/`, run `npm run sync` to copy the new build into the native projects.

To regenerate the icon and splash screen after editing `assets/logo.png`: `npm run assets`.

## Before releasing

1. **Name and app id.** Replace the placeholders `My Little Town` and `com.example.studytown`.
   The id is used in `capacitor.config.json`, `android/app/build.gradle` (`namespace`, `applicationId`),
   `android/app/src/main/res/values/strings.xml`, the Java package folder under
   `android/app/src/main/java/`, and the bundle identifier in Xcode. The app id cannot be changed
   after the app is published.
2. **Android.** Create a signing key, build a release bundle in Android Studio
   (Build > Generate Signed App Bundle) and upload it in the Google Play Console.
3. **iOS.** Open `ios/App/App.xcodeproj` in Xcode, choose your team under Signing & Capabilities,
   then Product > Archive and upload to App Store Connect. This needs an Apple Developer account.

## Notes and known limits

- The timer counts wall-clock time, so it keeps counting while the phone is locked or the
  app is in the background.
- On Android the "time's up" notification can arrive a little late when the phone is in
  battery-saving (Doze) mode, because the app does not request the exact-alarm permission.
- As a guest, data lives only on the device and uninstalling deletes the town. With an account
  it is backed up and merged back when you log in on any device.
- The cloud backup is uploaded when a session ends, when the app goes to the background and when
  you log out, at most about once a minute otherwise. A session that is still running stays on the device.
